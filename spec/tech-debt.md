## TD-01. Сохранение загруженных JS/TS фабрик основной сессии

**Где:** [WorkspaceBridge.relocate/rescope](../src/host.ts), регистрация [index.ts](../src/index.ts), механизм extensions/custom tools в omp 18.11.0. Связано с NAV-04 и [F7](future-features.md#f7).

**Цена:** после A → B основная сессия продолжает использовать загруженные extensions/custom tools A; новые фабрики B не появляются автоматически.
Фабрика, захватившая cwd или ресурс при старте, может сохранить состояние A. Переключение инструкций, настроек, MCP, LSP и памяти не пересоздаёт произвольные JS/TS замыкания.
Частота, время и стоимость последствия не измерялись. Новый сабагент B загружает свои фабрики заново и этим ограничением не затронут.

**Почему отложено:** пользователь явно принял сохранение загруженных JS/TS extensions/custom tools основной сессии для первой версии. Полная перезагрузка требует закрытия ресурсов и безопасного переноса регистраций без потери навигации и состояния сессии.

**Когда браться:** возникает реальный сценарий, где после переезда обязательно автоматически подключить фабрики B или выгрузить фабрики A; выполнить F7 с проверками регистрации, закрытия ресурсов и восстановления.

**Найдено:** 2026-10-13, осмотр управления ресурсами и subprocess-тест [runtime.test.ts](../test/runtime.test.ts), где custom tool целевого проекта не загружается при успешном переезде.
