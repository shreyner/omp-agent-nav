# Будущие возможности

F1–F6 согласованы вместе с первоначальной v1; F7 добавлен по принятому решению сохранять фабрики основной сессии.
Все пункты имеют статус **запланировано после v1**. При выборе этапа добавить его контракт, требования и проверки; после реализации перенести действующее поведение в основные документы.

<a id="f1"></a>
## F1. Append проектного контекста и prompt cache

**Назначение:** обновлять проектный контекст без полной пересборки начального prompt.
**Зависимости:** правильная релокация, модель отмены прежних инструкций и измерения кэша провайдера.
**Условие возврата:** измеримые затраты на повторный prompt при частых переездах.
**Готовность:** прежние инструкции не действуют, инструкции цели действуют; сохранение кэша и выигрыш измерены.

<a id="f2"></a>
## F2. Последовательные пакеты и вложенная навигация

**Назначение:** поддержать управляемый `move → read → edit` в одном последовательном исполнении.
**Зависимости:** граница применения, контекст исполнения, порядок и отмена вложенных вызовов.
**Условие возврата:** воспроизводимые сценарии, где ограничение одиночного пакета мешает работе.
**Готовность:** каждое действие использует нужный cwd; ошибка move не допускает последующий edit в неверной цели.

<a id="f3"></a>
## F3. Межпроцессное владение и обзор проектов

**Назначение:** согласовать занятость worktree между разными процессами omp и общий обзор разрешённых проектов.
**Зависимости:** проверенная принадлежность Git-проекту, протокол владения и восстановление после аварии.
**Условие возврата:** несколько сессий omp используют один worktree или нужен общий обзор.
**Готовность:** работающий worktree нельзя удалить другой сессией; устаревшее владение после аварии снимается проверяемым способом.
V1 учитывает сабагентов текущего процесса и штатный Git lock.

<a id="f4"></a>
## F4. Быстрый clone внутри primary

**Назначение:** ускорить материализацию worktree внутри primary при сохранении точного path.
**Зависимости:** безопасный clone backend с исключением создаваемого и соседних worktree.
**Условие возврата:** измеренная заметная стоимость обычного создания в реальном проекте.
**Готовность:** нет рекурсивного копирования и потери данных; выигрыш относительно v1 измерен.

<a id="f5"></a>
## F5. Перенос изменений и создание вместе с входом

**Назначение:** по явному запросу перенести незакоммиченную работу в worktree и объединить создание с входом.
**Зависимости:** контракт конфликтов и полное восстановление пользовательских данных при ошибке.
**Условие возврата:** нужно изолировать уже начатую правку или часто выполняются create/enter подряд.
**Готовность:** данные сохраняются при всех ошибках; перенос остаётся явным действием, а не скрытым значением по умолчанию.

<a id="f6"></a>
## F6. Упаковка и более широкая совместимость

**Назначение:** расширить установку и поддерживаемые версии после штатного extension-подключения для 18.10.3 (миграция на 18.11.0 выполнена 2026-10-15).
**Зависимости:** воспроизводимые проверки совместимости и поведения, документация extensions.
**Условие возврата:** готовность к распространению или запрос на обновление omp.
**Готовность:** документированная установка и проверенная матрица версий; неподдерживаемые версии дают понятную ошибку.
Выполнено 2026-10-16 в этой поставке: матрица проверенных версий (18.11.0, 18.11.1) в `SUPPORTED_OMP_VERSIONS` + runner `bin/matrix.ts` + процедура в [mechanics.md](mechanics.md) ([V19](verification.md#v19)); приватный локальный git-репозиторий без remote, готовый к push; установка на другую машину документирована клоном ([README.md](README.md)).
Остаток F6: публикация или иные каналы распространения (например, marketplace) и обновление глобальной версии omp на машине пользователя.
Подключение через конфигурацию перенесено в текущую работу по прямому поручению пользователя; его готовность определяется новыми runtime проверками, а не статусом F6.
Работа на выбранной опубликованной версии уже входит в v1. Upstream API — только условная работа, если внутренний bridge новой версии не даёт необходимого механизма.
Публикация и глобальная установка требуют отдельного разрешённого действия.

<a id="f7"></a>
## F7. Перезагрузка JS/TS extensions/custom tools основной сессии

**Назначение:** после переезда выгрузить фабрики A и загрузить фабрики B, сохранив навигацию, session ID и историю.
**Зависимости:** регистрация и закрытие ресурсов на уровне сессии, безопасная передача состояния фабрики и восстановление при ошибке загрузки.
**Условие возврата:** реальная задача требует автоматически включить фабрику цели или исключить прежнюю фабрику после перехода.
**Готовность:** инструменты, команды, hooks и контекст относятся к B; регистрации и ресурсы A закрыты; A → B → A не дублирует hooks/tools; ошибка reload возвращает согласованное состояние A.
Связанное принятое ограничение v1 — [TD-01](tech-debt.md#td-01); новый сабагент уже загружается по цели.
